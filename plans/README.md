## Findings considered and rejected

- Recolor every small `hover:bg-muted` icon/chip in the app: rejected for this
  pass. Small control feedback does not mask the gradient like large card/row
  surfaces, and a global rewrite would create unnecessary visual churn.
- Make Select/Combobox popovers translucent: rejected. They are portaled and
  may not sit above a gradient-painted ancestor, so an opaque semantic popover
  is the safer readable surface.
- Add hover styling to every text field: rejected. Focus, invalid, and disabled
  states already communicate interaction; the reported defect is the opaque
  surface, not missing field motion.
- Add autofill engine hacks and `color-scheme` in the same patch: deferred.
  This is a valid browser-specific audit item but needs Chromium/WebKit testing
  and is independent of the reported Gradient masking.
- Add shimmer: rejected. The request concerns color adaptation; centralizing
  the existing pulse fixes that without extra paint cost or motion.
- Recolor brand, cover-art, destructive, and reader overlay literals: rejected
  as intentional semantic/brand imagery rather than theme leaks.
- Reader loading localization/live-region work: deferred as a separate
  accessibility/i18n task unrelated to theme surfaces.
